# 当前 Skill 审计

审计日期：2026-07-24

## v1 基线

原 ZIP 含 19 个文件：`SKILL.md`、UI 元数据、2 个原创装饰资产、预览壳、8 个 references 和 9 个 Python 脚本。基线 `scripts/self_test.py` 11/11 通过。

稳定能力：

- Markdown/TXT/HTML 块解析与原文顺序检查。
- 五类主题检测、微信内联 HTML 基线、三色限制。
- 900×383/900×500/900×900 图片变体和压缩。
- SVG 栅格化、预览页、375/390/430px、深色模拟、富文本复制。
- 素材登记、Openverse/Pexels/Iconify 初始适配。
- 微信图片/封面上传、草稿创建、pending 未知状态保护与内置 Mock 测试。

## 主要缺口

- 直接围绕 HTML 包工作，缺少稳定、可迁移的文章中间格式。
- 只有一次性排版，没有资料盘点、多格式解析、内容审阅、锁定/版本回退闭环。
- 个人素材仓库、统一连接器、版权报告与多维排序缺失。
- 只有单一视觉方向，未提供三套结构差异明显的 Design Brief。
- HTML 清理/CSS 内联与 SVG 主动内容清理不完整。
- `materials.py` 允许结果 JSON 中任意下载 URL，存在 SSRF 风险；素材/封面路径也缺少越界保护。
- 测试只有 11 个实现级用例，缺少 20 个场景目录、单元/集成/安全与完整示例。
- 缺少 README、AGENTS、配置模板、工具探测、决策、状态与限制文档。

## v2.1 视觉质量复审

用户明确判定 v1/早期 v2 的历史成品缺少审美与冲击力，因此旧封面、插画、GIF、截图、奶油纸张配色、固定左边线标题和通用卡片均降为反例基线。它们只保留用于兼容回归，不能进入新设计参考、Design DNA 或示例交付。

新增强制 Design Read、三只视觉旋钮、单一视觉母题、内容自检、视觉预检和 `design_quality.py`。高设计任务缺原创主视觉、少于三种节奏、只使用 baseline fragment 或引用旧视觉时直接失败。

端到端案例已从文章、概念、HTML、SVG、GIF、PNG、封面、组件到截图全部重做。新例采用“在观点噪声中捕捉真实行为信号”，没有复用历史视觉资产或布局。
